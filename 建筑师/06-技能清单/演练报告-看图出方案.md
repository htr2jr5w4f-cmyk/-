# 演练报告——看图出方案（两层住宅）

适用州：不适用（工具与技能检验；方案内容为 QLD）｜资料核对日期：2026-11-21｜状态：已完成演练（图纸为假设演练图纸，非真实项目）；脚本修复已通过 42 项回归测试

## 摘要
本文记录一次「看图出方案」端到端演练：用 ezdxf 生成一套假设的布里斯班两层住宅图纸（底层、上层、屋面三张平面，6 个指定图层，另用 PyMuPDF 出 1:100 A3 PDF），只用 `dxf算量.py` 和 `pdf图纸量尺.py` 量取，再填工程量计算表和进度计划模板的副本，最后按「看图出方案」技能写出完整方案。结论：两个脚本的量取结果和设计值完全一致（DXF 与 PDF 1:100 差 0，两点校准差 ≤0.07%），图纸错误（尺寸文字被改写）也能查出来；但工具和模板都按「一张图、一层楼」设计，用在多图合一的 DXF 和两层住宅上要靠人工补很多。修了 2 个脚本问题，改了 3 个 SKILL.md，其余列为改进建议。对省钱的作用：把这些坑提前写进技能，真实项目时少走弯路，少漏算两层特有的法定成本（脚手架、临边防护、栏杆）。

## 2. 好用的地方

1. **量取准确**：所有设计值都被准确读出（外包面积 140 / 120、内皮 128.25 / 113.49、内墙 26.9 / 38.45、湿区 8.0625 / 15.675、屋面 147.84 / 29.12、洞口 4.565）。PDF 按比例和 DXF 结果完全一致；两点校准（在 100 dpi PNG 上读 14000 尺寸线两端像素）误差 0.07%，远低于技能定的 1% 复核线。
2. **图纸错误能自动查出**：`dxf算量.py` 在尺寸表里直接标「6.000 m，图上文字被改写为「5900」」，`pdf图纸量尺.py 文字` 的「可疑尺寸数字」也列出了 5900 → 直接变成 RFI-01。
3. **块属性好用**：门窗块的 MARK 属性被当成文字读出，块数量 + 编号可以和门窗表逐项对数（底层 13、上层 14，对上）。
4. **PDF 图层（OCG）过滤好用**：`--图层 外墙 内墙 …` 一次把墙、湿区、门窗分开，不用按颜色猜；无描边的湿区填充单独成组，面积正确。
5. **HATCH 面积**：带图案填充（ANSI31）的湿区 HATCH 面积正确，不受图案影响。
6. **模板公式可靠**：计算表和进度表副本经 LibreOffice 重算，所有公式结果与手算一致；进度表 36 道工序、最多 3 个紧前，没有「紧前编号错误」。工期格写文字「待按项目填写」时 `N()` 按 0 处理，逻辑照常计算——正好满足「不编工期」的要求。
7. **技能流程清楚**：看图出方案的「缺图 → 定性 → 5 部分 → 自查」顺序，和工作流程文件的 14 项缺图清单，直接就能套用。

| P7 | 房间周长（踢脚、顶角线用）量不出来：房间没有画成闭合多段线，只能按墙线手算 | R20、R21 全靠手算 | 建议设计方出图时加房间边界图层，或在 SKILL 里提示（已写入） |
